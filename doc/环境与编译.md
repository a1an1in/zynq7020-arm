# 环境与编译 —— PetaLinux 2021.1 (Zynq-7020)

本模块覆盖该工程的两大块:**构建环境搭建**(Docker 镜像、SDK、离线包、进容器)
与 **工程编译/打包**(`src`)。目标平台为 **Zynq-7020**
(XC7Z020, 32 位 ARM Cortex-A9),基于 Ubuntu 18.04 + PetaLinux **2021.1**。

> 环境搭建只做一次(或换机时重做);日常开发进容器直接编译即可。

---

## 一、配置docker编译环境

### 1. 目录约定

`sdk/` 是**唯一持久化卷**(挂到容器内 `/opt/xilinx`),换机时整体拷走 + 重建镜像即可。

```text
sdk/
├── petalinux/   # SDK 本体(安装器写入;settings.sh 也在其中)
├── downloads/   # 离线源码 pre-mirror
└── sstate/      # 32 位 sstate 缓存(子目录 arm)
```

工程放在仓库根 `src/`(容器内 `/work/src`),不装进 sdk 卷,随代码一起管理。

### 2. 前置资源

已下载以下文件:

- `petalinux-v2021.1-final-installer.run`
- `downloads_2021.1_update1.tar.gz`
- `sstate_arm_2021.1.tar.gz`(32 位,Zynq-7000 用这个)

### 3. 构建 Docker 镜像(一次性)

镜像只装 OS + PetaLinux 依赖,**不含 SDK**。

```bash
./utils/build-image.sh
```

可自定义镜像名(后续步骤需一致)与宿主 UID/GID:

```bash
IMG_NAME=petalinux:2021.1 ./utils/build-image.sh
HOST_UID=$(id -u) HOST_GID=$(id -g) ./utils/build-image.sh
```

### 4. 安装 SDK 到 sdk/ 卷

安装器默认从若干候选路径找;找不到时用 `PETALINUX_INSTALLER` 显式指定:

```bash
PETALINUX_INSTALLER=<绝对路径> ./utils/install-sdk.sh
./utils/install-sdk.sh
```

- 非交互自动应答许可(`docker/scripts/auto-install.sh`,基于 expect)。
- 想亲眼确认安装界面,可加 `--interactive` 在前台运行按提示操作。
- 完成标志是生成 `sdk/petalinux/settings.sh`。安装失败时可用
  `SAP_EXP_TTY=1` 重跑查看安装器原始输出。

### 5. 解压离线包(可选但推荐,离线编译)

```bash
./utils/unpack-offline.sh
```

离线包 `.tar.gz` 默认从 `docker/archives/`(或系统统一归档目录)找,也可显式指定:

```bash
DOWNLOADS_TGZ=<路径> SSTATEGZ=<路径> ./utils/unpack-offline.sh
```

解压后 `downloads` 落到 `sdk/downloads`,`sstate` 落到 `sdk/sstate/arm`。
离线包较大,解压完成后原 `.tar.gz` 可删除以省空间。

### 6. 进入容器(日常开发入口)

```bash
./utils/devops.sh                    # 交互 shell, /work 是仓库根目录
source /opt/xilinx/petalinux/settings.sh #进入容器后先激活环境， 后续配置petalinux
```

## 二、petalinux工程配置

- 工程位置:仓库根 `src`(容器内 `/work/src`)
- 前置:已 `source /opt/xilinx/petalinux/settings.sh`

### 1. 从零创建工程并导入硬件(推荐先看)

这一步决定工程骨架与硬件描述。**已有工程可跳过 1.1**,直接核对/导入 XSA。

#### 1.1 创建工程(zynq 模板,32 位)

```bash
./utils/devops.sh
source /opt/xilinx/petalinux/settings.sh
cd /work

# 7020 是 32 位,务必用 --template zynq,勿用 zynqMP
petalinux-create -t project --template zynq --name src
cd src
```

> 若仓库根已存在 `src` 同名目录,跳过创建,直接从 1.2 开始导入硬件。

#### 1.2 放置硬件描述(XSA / BSP)

XSA 统一放在 `docker/archives/`(安装器/离线包本就归档于此,集中管理;容器内即
`/work/docker/archives`):

```text
docker/archives/
├── petalinux-v2021.1-final-installer.run   # 安装器
├── system.xsa                              # Vivado 导出的硬件描述
└── system_wrapper.bit                      # 硬件位流
```

> 不建议把 XSA 直接混进工程自己的 `project-spec/hw-description/`;源放
> archives,导入时由 petalinux 复制成工程内 `system.xsa`。

#### 1.3 导入硬件到工程

```bash
cd /work
# 从 archives 目录导入(petalinux 自动复制并重命名为工程内 system.xsa)
petalinux-config --get-hw-description /work/docker/archives
```

若目录里同时有多个 `.xsa`,需指定确切文件:

```bash
petalinux-config --get-hw-description /work/docker/archives/system.xsa
```

`--get-hw-description` 从源复制并重命名为 `system.xsa`
(落在 `project-spec/hw-description/`)。

> **坑**:不要把工程自己的 `project-spec/hw-description` 目录当源传给
> `--get-hw-description`,那会报 `No XSA found` / `cannot stat my_system.xsa`。
> 源必须指向该目录**之外**的位置(例如 `docker/archives`)。

#### 1.4 离线编译配置(pre-mirror / local sstate)

两种方式任选:

**方式 A(推荐,非交互)** —— 直接改 `project-spec/configs/config`:

```text
CONFIG_PRE_MIRROR_URL="file:///opt/xilinx/downloads"
CONFIG_YOCTO_LOCAL_SSTATE_FEEDS_URL="/opt/xilinx/sstate /arm"
# CONFIG_YOCTO_NETWORK_SSTATE_FEEDS is not set
```

进容器静默采纳:

```bash
./utils/devops.sh
cd /work/src
petalinux-config --silentconfig
```

**方式 B(GUI)** —— `petalinux-config` 在 Yocto Settings 里设置:
`pre-mirror url = file:///opt/xilinx/downloads`、
`local sstate feeds = /opt/xilinx/sstate  /arm`,并取消勾选 `Enable Network sstate feeds`。


## 三、使用脚本 devops.sh 简化编译与打包(日常推荐)

`devops.sh` 在宿主执行,把后续参数**原样丢进容器跑**,免交互。因为宿主仓库根
挂到容器 `/work`,你在宿主改的 `config`/XSA 与工程文件容器内就是同一份,
无需重复配置:

```bash
# 一键编译全部镜像
./utils/devops.sh petalinux-build

# 编译并打包 BOOT.BIN(FSBL + U-Boot + FPGA bitstream)
./utils/devops.sh petalinux-package --boot --u-boot --fpga --force

# 清理上次编译
./utils/devops.sh petalinux-build -x distclean

# windows 执行wsl环境编译命令
wsl bash -lc 'cd /home/alan/workspace/zynq/zynq7020-arm && ./utils/devops.sh petalinux-build'
wsl bash -lc 'cd /home/alan/workspace/zynq/zynq7020-arm && ./utils/devops.sh petalinux-package --boot --u-boot --fpga --force'
wsl bash -lc './utils/devops.sh petalinux-build -x distclean'
```

若想逐步操作/查看中间输出,先进容器再手动执行:

```bash
./utils/devops.sh
source /opt/xilinx/petalinux/settings.sh
cd /work/src
petalinux-build
petalinux-package --boot --u-boot --fpga --force
```

生成的 `BOOT.BIN` 位于 `src/images/linux/`(PetaLinux 的 images 目录),
可直接拷贝到 SD 卡启动。

### 常见产物位置

| 产物 | 位置 |
|------|------|
| 硬件描述 | `src/project-spec/hw-description/`(`system.xsa`、`system_wrapper.bit`、`ps7_init.*`) |
| 编译输出 | `src/build/` |
| 启动镜像 | `src/images/linux/BOOT.BIN`(打包后) |

## 四、替换 XSA / bit（更新 PL 逻辑）

> 一句话：**只替换归档源 `docker/archives/` 里的 XSA；`hw-description/` 不用手动改**——它是 petalinux
> 重新导入时**自动刷新**的产出物。

**“源”与“产出”的关系**

| 位置 | 角色 | 是否手动作 | 说明 |
|---|---|---|---|
| `docker/archives/system.xsa`（+`system_wrapper.bit`） | **归档源** | ✅ 替换此处 | 统一归档 / `--get-hw-description` 的导入源；位流实际内含在 XSA |
| `project-spec/hw-description/` | **petalinux 产出** | ❌ 不手动改 | 由 `--get-hw-description` 复制 XSA 并解包出 `system_wrapper.bit`、`ps7_init.c/tcl`、`system.hwh` 等 |

**操作步骤（容器内，路径为 `/work/docker/archives`）**

```sh
# 1) 替换归档源：直接覆盖；或（在 FPGA 仓库里）scripts/fpga.py ship-xsa --top aurora 自动拷贝至此
#      docker/archives/system.xsa          ← 新的 Vivado 导出 XSA
#      (可选) docker/archives/system_wrapper.bit ← 解包给人工取用的位流

# 2) 从源重新导入，让 petalinux 自动刷新 hw-description：
./utils/devops.sh petalinux-config --get-hw-description /work/docker/archives
#     └ 把新 XSA 复制成 hw-description/system.xsa，并重新解包出
#       system_wrapper.bit、ps7_init.*、system.hwh 全套，与固件打包保持一致。

# 3) 重新构建并重打 BOOT.BIN（把新 bit 嵌进去生效）：
./utils/devops.sh petalinux-build 
./utils/devops.sh petalinux-package --boot --u-boot --fpga --force

# 可以在windows运行的对应脚本
wsl bash -lc './utils/devops.sh petalinux-config --get-hw-description /work/docker/archives'
wsl bash -lc './utils/devops.sh petalinux-build'
wsl bash -lc './utils/devops.sh petalinux-package --boot --u-boot --fpga --force'
wsl bash -lc './utils/devops.sh petalinux-build -x cleanall -c petalinux-image-minimal && petalinux-build -c petalinux-image-minimal'

./utils/devops.sh petalinux-build -c device-tree
dtc -I dtb -O dts src/images/linux/system.dtb | grep -A6 'dma-channel@50000030'
./utils/devops.sh petalinux-build -x cleanall -c petalinux-image-minimal && petalinux-build -c petalinux-image-minimal
./utils/devops.sh petalinux-build -c petalinux-image-minimal
```

**提醒**

- 只手动覆盖 `hw-description/system.xsa` 而不重新导入，那些解包的 `ps7_init.*` / `system_wrapper.bit` / 硬件
  缓存不会同步，打包仍可能用旧的——务必走第 2 步刷新。
- 当前板的硬件是工程 **`fpga0`**（`xc7z020clg484-1`，含 AXI 以太网 + SDSoC OCL 区）导出的 XSA；
  `zynq7020-fpga` 里的 `run_led` 是后起的独立 demo 工程、两者位流不同。要用 `run_led` 的 PL 逻辑，需把它
  导出的 XSA 按上面流程替换进来，否则板上 PL 仍跑旧位流。
- 若想“频繁换 bit 而不重打 BOOT.BIN”，可改用 Linux 启动后**运行时加载**：本板默认**未装** `board-fpga-autoload`
  服务（`/lib/firmware` 不存在属正常，不影响现有功能——PL 由 boot.bin 位流在 FSBL/U-Boot 阶段已配好）；
  `fpgautil` 已位于 `/usr/bin`，需要时自行 `mkdir -p /lib/firmware/xilinx/...` 放入 `.bin/.dtbo` 并写开机脚本，
  或用 `fpgautil -b <bit.bin>` 手动加载。

## 五、坑提示

- 基镜像用 Ubuntu 18.04(PetaLinux 2021.1 官方支持),20.04 缺
  `libncurses5/libtinfo5`,易出问题。
- PetaLinux 安装器**拒绝 root 运行**,镜像内以 `plsdk` 用户执行,各脚本已用
  `-u plsdk` 处理。
- Zynq-7000 是 32 位:模板用 `--template zynq`,sstate 用 **arm**,不是
  aarch64。
- 离线编译务必按上文配置 pre-mirror 与 local sstate,并取消网络 sstate。

## 六、故障排查

### WSL2 “磁盘利用率 100%”

**先分清是「空间满」还是「I/O 打满」**,两者处理方式完全不同。

#### 1. 看 df,别被假象骗了

```bash
df -h    # 看 / 与 /mnt/c 的 Use%
df -i    # Yocto 小文件多,可能空间有剩但 inode 被耗尽
```

`/dev/loop0 ... 100% ... /mnt/wsl/docker-desktop/cli-tools` 是 Docker Desktop 的
**只读** CLI 工具镜像(iso9660),固定显示 100%,属正常现象,与构建无关。

#### 2. 空间类(`df` 里 `/` 或 `/mnt/c` 逼近 100%)

- 体积来源:`sdk/` 卷(PetaLinux + downloads + sstate 可到 60GB+)、
  `src/build/tmp` 与 `downloads`(数十 GB)、Docker 镜像/构建缓存;
  且 WSL2 的 `ext4.vhdx` **只涨不缩**,删了文件也不自动还给 Windows。
- 清理:`petalinux-build -x distclean`(或删 `build/tmp`)、删除已解压的离线
  `.tar.gz`、`docker system prune -a`。
- 别漏了 WSL 残留的交换文件:`%LOCALAPPDATA%\Temp\<GUID>\swap.vhdx`(每个约
  1GB,WSL 异常退出后会留下,本机一度有 8 个)。`wsl --shutdown` 之后可安全删除。
- 回收 vhdx 空洞:Windows 侧 `wsl --shutdown`,再
  `wsl --manage <发行版> --set-sparse true`(或 `diskpart` → `select vdisk` →
  `attach vdisk readonly` → `compact vdisk`)。
- 根治:把发行版迁到非系统盘(`wsl --export` / `--import`),或给 `sdk/`、`build/`
  换卷。

#### 3. I/O 打满类(Windows 任务管理器磁盘长期 100%,构建龟速)

根因通常是**内存太少 + 并发太高**,本项目已按此修复:

- WSL2 若只分到 4GB 内存且 `swap=0`(见 `%USERPROFILE%\.wslconfig`),而 bitbake
  默认按 nproc(16)并发,再加上 `conf/local.conf` 内的 `INHERIT += "rm_work"`
  (反复创建/删除 `build/tmp/work`,小文件 I/O 极大),内核就会不停回收并回读
  page cache,磁盘 I/O 持续饱和。
- 宿主 16 核 / 28GB 内存的建议配置(改完必须 `wsl --shutdown` 生效,
  会停掉 Docker Desktop 内所有容器):

  ```ini
  [wsl2]
  networkingMode=Mirrored
  memory=12GB
  processors=12
  swap=8GB

  [experimental]
  autoMemoryReclaim=gradual
  sparseVhd=true
  ```

- 并发已收敛在 [`petalinuxbsp.conf`](../src/project-spec/meta-user/conf/petalinuxbsp.conf:1):
  `BB_NUMBER_THREADS = "8"`、`PARALLEL_MAKE = "-j8"`;内存加大后可放宽
  (如 12/12)。
- 构建目录必须留在 WSL 的 ext4(即当前仓库位置,容器内 `/work`),
  **不要放到 `/mnt/c`**:9p 协议下 Yocto 的元数据操作会慢一个数量级。

#### 4. 验证

一键体检(空间 / inode / vhdx / 内存 / Docker 占用):

```bash
./utils/wsl-disk.sh
```

确认并发设置已生效(`bitbake` 不在 PATH 上,要用工程内的那个):

```bash
./utils/devops.sh bash -c 'cd /work/src/build && ../components/yocto/layers/core/bitbake/bin/bitbake -e virtual/kernel | grep -E "^(BB_NUMBER_THREADS|PARALLEL_MAKE)="'
# 期望输出:
#   BB_NUMBER_THREADS="8"
#   PARALLEL_MAKE="-j8"
```

再跑 `./utils/devops.sh petalinux-build`,任务管理器里磁盘应只在解包/链接阶段短时
冲高,而不再长期 100%。
