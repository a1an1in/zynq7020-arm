# Zynq(F6-7020) 调试与烧写方法

> 记录 Zynq-7020（米联客 F6-CZ06-7020）在 Linux / FPGA 开发调试过程中的镜像烧写与加载方法。
> 适用：PetaLinux 构建出 `BOOT.bin`、`image.ub`，Vivado 生成 `.bit`，及裸板 SDK 调试。

## 1. 核心概念

Zynq 是「一片芯片、两大部分」：

| 部分 | 叫法 | 内容 | 谁在做 |
|---|---|---|---|
| PS | ARM | 双核 Cortex-A9、运行 U-Boot / Linux / 裸板程序 | 软件（Linux / SDK 裸板）|
| PL | FPGA | 可编程逻辑（自定义 IP、FDMA、网口等）| 硬件（Vivado / Verilog）|

- **FSBL**（First Stage Boot Loader）上电时配置时钟/PL(bit)并引导 U-Boot。PetaLinux 会**自动生成并打包 FSBL**，无需手工用 Vitis 写。
- **`BOOT.bin`** = FSBL + U-Boot (+可选 `.bit`)，是 ARM 端真正的启动镜像。
- **FPGA(PL) 一般不是“单独烧”的**：量产时把 `.bit` 打进 `BOOT.bin`，上电由 FSBL 自动配进 PL；调试时再用 JTAG 单独下载。

## 2. 启动方式全家桶（BOOT MODE，板上拨码/MIO 决定）

| 方式 | 特性 | 用途 |
|---|---|---|
| **SD 卡** | FAT 分区放 `BOOT.bin + image.ub + boot.scr` | 开发期最灵活；改文件即改即用 |
| **QSPI Flash** | 板上 NOR Flash | **脱机/量产**，不插卡直接启动 |
| **JTAG** | Vivado/Vitis 临时加载，掉电丢失 | **调试**专用 |
| NAND / eMMC | 视板卡 | 部分板支持 |

F6-CZ06-7020 一般带 **QSPI + SD + JTAG**，拨码切换启动源。

## 3. 烧写 FPGA（PL，bit 流）

| 场景 | 做法 |
|---|---|
| 调试/临时（掉电无） | Vivado **Hardware Manager → Program Device** 下载 `.bit`（走 JTAG）|
| 脱机固话 | `.bit` 打进 `BOOT.bin`，随 QSPI/SD 启动由 FSBL 自动配置 PL |
| Linux 运行中重配 | `/dev/fpga*` 或 DT `fpga-region` overlay 在线加载 |

打包 bit 进启动镜像（PetaLinux）：
```bash
petalinux-package --boot --fsbl ./fsbl.elf --fpga ./xxx.bit --uboot
```
> 量产 Zynq 的 FPGA 靠 FSBL 自动配置，不单独“烧” PL。

## 4. 烧写 ARM（PS，启动镜像）

把 `BOOT.bin` 写入不同介质：

| 目标 | 手段 |
|---|---|
| **SD** | 挂载 FAT 分区后 `cp BOOT.bin image.ub boot.scr` |
| **QSPI** | **U-Boot**：`sf probe; sf erase; sf write`；或 **Linux**：`flashcp BOOT.bin /dev/mtdX`，拨码切 QSPI |
| QSPI(经 JTAG) | Vitis/XSCT：`program_flash -flash_type qspi-x4-single -fsbl … -file BOOT.bin` |
| 内存在线(调试) | XSCT：`connect → targets → dow` 下载 ELF 到 RAM 跑 |

## 5. 调试阶段推荐流程（避免频繁插拔 SD）

**核心思路**：SD 只负责一次性启动，之后 Linux 的修改走 **NFS/TFTP**，FPGA 的修改走 **JTAG**，量产后统一进 **QSPI**。

```
SD(唯一启动：BOOT.bin + u-boot 网络启动参数)
 ├─ Linux 修改 ──→ TFTP(image.ub) + NFS(rootfs)   ← 主机改
 └─ FPGA 修改 ──→ JTAG (Vivado 下载 .bit)          ← 临时重配 PL
量产/脱机                     → QSPI (含 bit 的 BOOT.bin)
```

> 这样 **SD 插上就不用拔**，所有迭代都在主机端完成。

### 5.1 主机端搭 TFTP + NFS（Debian/Ubuntu）
```bash
sudo apt install tftpd-hpa nfs-kernel-server
# TFTP 目录（放 image.ub）：/srv/tftp
# NFS 导出：/srv/nfs/rootfs  *(rw,sync,no_root_squash,no_subtree_check)
sudo systemctl restart tftpd-hpa nfs-kernel-server
```

### 5.2 U-Boot 网络启动参数（固化到 boot.scr / env）
```
setenv serverip 192.168.1.10        # host IP
setenv ipaddr 192.168.1.100         # 板子 IP
setenv bootargs 'console=ttyPS0,115200 root=/dev/nfs \
  nfsroot=192.168.1.10:/srv/nfs/rootfs rw \
  ip=192.168.1.100::192.168.1.1:255.255.255.0::eth0:off'
tftpboot 0x2000000 image.ub; bootm 0x2000000
```
之后换 kernel 只需覆盖主机 TFTP 目录里的 `image.ub`，重启即生效，**全程不碰 SD**。

### 5.3 启动后单独重配 FPGA（配合 Linux 调试）
Vivado Hardware Manager → Program Device 下载新 `.bit`（或 XSCT `fpga -file xx.bit`）。只重配 PL、不影响 PS/Linux。

**前提（务必注意）**：
- ✅ 新 bit **接口不变**（相同地址/中断/ip）：可直接配合 Linux 应用/字符设备调试。
- ⚠️ 新 bit **变了接口/地址/新增外设**：Linux 设备树(DT)仍是旧的，驱动不 probe → 需更新 DT/驱动，通常要重启让「新 bit + 新 DT」一起生效。

**两个坑**：
1. JTAG 重配 PL 会打断在途 AXI 事务，配合的应用/驱动要容忍重连（或调完再起）。
2. 新 bit 内部状态是新的，若驱动依赖旧寄存器设置，需重新初始化或复位 IP core。

## 6. 何时用什么（速查）

| 需求 | 最优方式 |
|---|---|
| 日常快速出可启动镜像 | **SD**（FAT 拷 BOOT.bin/image.ub） |
| 反复改 kernel/dt/驱动/应用 | **TFTP image.ub + NFS rootfs** |
| 调 PL 纯逻辑（3-1 类实验） | **JTAG**（Vivado 下载 bit） |
| Linux 运行中换 PL bit、接口不变 | **JTAG 重配** + Linux 协同调试 |
| 脱机 / 量产 | **QSPI**（含 bit 的 BOOT.bin） |

## 7. 工具依赖速查

| 工具 | 用途 | 是否必需（只做 Linux） |
|---|---|---|
| Vivado | 建硬件工程、管脚/时序、导出 `.xsa` | ✅ 必需 |
| Vitis(SDK) | 写/调试 PS 裸板、生成 FSBL | ⭕ 不写裸板则不需要（FSBL 由 PetaLinux 自动生成） |
| PetaLinux | 构建打包 Linux、BOOT.bin | ✅ 必需（在做本项目） |
