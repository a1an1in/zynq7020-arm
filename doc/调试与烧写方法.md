# Zynq(F6-7020) 调试与烧写方法

> 记录 Zynq-7020（米联客 F6-CZ06-7020）在 Linux / FPGA 开发调试过程中的镜像烧写与加载方法。
> 适用：PetaLinux 构建出 `BOOT.bin`、`image.ub`，Vivado 生成 `.bit`，及裸板 SDK 调试。

## 1. 核心概念

Zynq 是「一片芯片、两大部分」：

| 部分 | 叫法 | 内容 | 谁在做 |
|---|---|---|---|
| PS | ARM | 双核 Cortex-A9、运行 U-Boot / Linux / 裸板程序 | 软件（Linux / SDK 裸板）|
| PL | FPGA | 可编程逻辑（自定义 IP、FDMA、网口等）| 硬件（Vivado / Verilog）|

### 1.1 启动方式全家桶（BOOT MODE，板上拨码/MIO 决定）

| 方式 | 特性 | 用途 |
|---|---|---|
| **SD 卡** | FAT 分区放 `BOOT.bin + image.ub + boot.scr` | 开发期最灵活；改文件即改即用 |
| **QSPI Flash** | 板上 NOR Flash | **脱机/量产**，不插卡直接启动 |
| **JTAG** | Vivado/Vitis 临时加载，掉电丢失 | **调试**专用 |
| NAND / eMMC | 视板卡 | 部分板支持 |

F6-CZ06-7020 一般带 **QSPI + SD + JTAG**，拨码切换启动源。

## 2. 烧写前准备：ARM / FPGA 各自的镜像怎么生成

烧写前先弄清「要烧的文件从哪来」。Zynq 烧的是两类镜像，分别由不同代码仓库 / 工具链产出：

| 端 | 关键文件 | 作用 | 谁生成 / 在哪 |
|---|---|---|---|
| **ARM(PS)** | `FSBL`→打包成 `BOOT.bin`、`image.ub` | 引导 CPU + 配置外设/时钟/启动内核 | PetaLinux / SDK；硬件描述来自 zynq7020-fpga 的 `.xsa` |
| **FPGA(PL)** | `.bit`（bit 流，可选 `.xsa`） | 配置可编程逻辑 | Vivado，工程在 **`zynq7020-fpga`** 子模块 |

> 本仓库布局：父仓库 `zynq` 下有两个子模块——`zynq7020-arm`（软件/烧写工具）与 **`zynq7020-fpga`（FPGA/PL 硬件工程）**。本篇烧写工具在 `zynq7020-arm/utils/flash-sd.sh`。

### 2.1 FPGA 侧：在 zynq7020-fpga 生成 bit（及 XSA）

FPGA 工程由 `zynq7020-fpga` 仓库以「脚本化 + 多工程分目录」管理（`projects/<工程名>/`），用 `scripts/fpga.py` 统一驱动 Vivado：

```bash
cd /home/alan/workspace/zynq/zynq7020-fpga
python3 scripts/fpga.py build --top run_led     # 建工程 → 综合 → 实现 → 出 bit → 导 XSA
```

产物位置：
- bit 流：`build/<工程名>_prj/<工程名>.runs/impl_1/<工程名>.bit`
- 硬件描述（含 Zynq PS 的工程才有）：`build/<工程名>.xsa` ← **给软件侧(ARM/PetaLinux/SDK)用**

其他常用子命令：`program`（JTAG 直接烧板）、`sim`、`clean`。新建工程：`cp -r projects/proj1_template projects/<工程名>` 放源码到 `src/`、约束到 `constraints/`、IP 到 `ip/`。

### 2.2 ARM 侧：PetaLinux / SDK 生成 BOOT.bin 与 image.ub

- **FSBL**（First Stage Boot Loader）上电时配置时钟/PL(bit)并引导 U-Boot。PetaLinux 会**自动生成并打包 FSBL**，无需手工用 Vitis 写。
- **`BOOT.bin`** = FSBL + U-Boot (+可选 `.bit`)，是 ARM 端真正的启动镜像。
- 先把上面 zynq7020-fpga 导出的 `.xsa` 交给 PetaLinux/SDK，再打包：
```bash
petalinux-package --boot --fsbl ./fsbl.elf --fpga ./xxx.bit --uboot
# 不带 --fpga 则不含 bit（纯 ARM 启动）
# 产物 BOOT.bin 配合 image.ub（内核+DT+可选 ramdisk）一起烧
```
> `.bit`/`.xsa` 来自 zynq7020-fpga 的 `build/`；`--fpga` 用 `.bit`，SDK/`-xsa` 用 `.xsa`。

### 2.3 先想清楚走哪条路（烧前规划）

| 阶段 | 建议介质 | 理由 |
|---|---|---|
| FPGA 纯逻辑调试 | **JTAG** 直接烧 `.bit` | 掉电无、迭代快 |
| 完整 ARM+FPGA 联调 | **SD**（BOOT.bin 含 bit） | 灵活、易改 |
| 脱机/量产 | **QSPI**（BOOT.bin 含 bit） | 掉电保留、可固化 |

> 量产 Zynq 的 FPGA 靠 FSBL 自动配置，不单独“烧” PL。

## 3. 完整烧写 SD 卡

把 `BOOT.bin`、`image.ub`、`boot.scr` 写进 SD 卡的 FAT(BOOT) 分区。开发期最灵活，改文件即改即用；量产/脱机多卡场景再走 QSPI（见 §5）。完整 SOP 如下。

### 3.1 脚本 + usbipd 全流程

> 本工程的 SD 卡烧写统一用脚本 `utils/flash-sd.sh`（子命令化），配合 WSL2 的 `usbipd` 完成「识别 → 分区 → 刷包 → 归还」全流程。

| 子命令 | 作用 |
|---|---|
| `list` / `detect` | 识别当前 SD 卡（WSL 可移动盘 + usbipd 读卡器状态） |
| `release` | 归还读卡器给 Windows（`usbipd detach`，会弹 UAC，点允许） |
| `part` | 只做分区 + 格式化（FAT32 1-100MiB 可引导 + ext4 到盘尾） |
| `mkfs` / `format` | 只重格式化已有分区（保留分区表，自动卸载残留挂载） |
| `flash [源]` | 刷包；若 SD 卡未分区则先自动分区再刷包（省略 `[源]` 时默认官方出厂包） |

`flash [源]` 的「源」一律为**目录路径**，省略时默认官方出厂包；刷本工程产物传 `<工程>/src/images/linux` 目录。脚本**不带任何参数时直接打印帮助**（`./utils/flash-sd.sh help` 同效）。

### 3.2 完整流程（分阶段）

**阶段 0 · 一次性准备（Windows 管理员 PowerShell）**
```powershell
usbipd list                       # 记下读卡器 BUSID（本机常见 1-3）
usbipd bind --busid 1-3           # 仅首次，把读卡器绑定给 usbipd（Windows 盘符会消失，正常）
```
> BusID 每次插入可能变化，用 `usbipd list` 实时查。

**阶段 1 · 把卡接进 WSL2（每次要用时）**
```powershell
usbipd attach --wsl --busid 1-3
```
WSL 里 `lsblk` 应能看到 `/dev/sdg 29.2G`（RM=1）。

**阶段 2 · 识别**
```bash
cd /home/alan/workspace/zynq/zynq7020-arm
./utils/flash-sd.sh list
```

**阶段 3 · 分区/格式化/刷写（选一种）**
```bash
# 不带子命令=打印帮助；刷包方式：
./utils/flash-sd.sh flash                    # A. 刷官方出厂包（默认源，常用）
./utils/flash-sd.sh flash ./src/images/linux # B. 刷本工程产物
./utils/flash-sd.sh part                     # C. 只要分区+格式化
./utils/flash-sd.sh mkfs                     # D. 只重格式化、保留分区表
```
每步交互：输设备 `/dev/sdg` → 输 `YES` → 输 sudo 密码。刷完检查：
```bash
lsblk -o NAME,SIZE,FSTYPE,LABEL /dev/sdg
```

**阶段 4 · 归还读卡器（拔卡前必须做）**
```bash
./utils/flash-sd.sh release
```
或 Windows 管理员 PS 手动：
```powershell
usbipd detach --busid 1-3
```
> ⚠️ 若 `usbipd list` 里 STATE 是 `Shared (forced)`，需再加 `usbipd unbind --busid 1-3` 归还给 Windows 驱动，否则直接拔会「Windows、WSL 都看不到」。

**阶段 5 · Windows 确认 + 安全拔出**
- Win+R → `diskmgmt.msc` 打开磁盘管理，必要时给 FAT(BOOT) 分区分配盘符。
- ext4(rootfs) 分区 Windows 原生不认、不给盘符属正常，检查请回 WSL。
- 托盘「安全弹出」→ 拔卡。

**阶段 6 · 开发板启动**
卡插 SD 槽，拨码改 SD 启动 → 上电。量产/脱机可后续写入 QSPI。

**阶段 7 · 下次再接进 WSL2**
回到阶段 1 重新 `usbipd attach --wsl --busid X`。

### 3.3 usbipd 三种状态速查（最容易混）

| 状态 | 含义 | 处理命令 |
|---|---|---|
| `Attached` | 已接进 WSL，占用中 | `usbipd detach --busid X` |
| `Shared (forced)` | bind 残留、Windows 未接管 | `usbipd unbind --busid X` |
| `Not shared` | 正常归 Windows | 无需操作 |

### 3.4 注意点

- 出厂包默认目录位于 **C 盘**（`wsl` 映射为 `/mnt/c/.../sdcard_image`），内含约 **420M 的 rootfs.tar.gz**，从 C 盘读取慢属正常；脚本已打印大小提示，`pv`（`apt install pv`）可显示进度。
- `flash` 在 SD 卡**已有分区时默认不重分区**，只刷内容；要彻底重排用 `part`。
- 根文件系统形态：出厂包 / 工程放到 `ext4` 分区；若工程用 `image.ub` 内 ramdisk 启动，ext4 留空属正常。

## 4. 开发期迭代：SSH/FTP 登板，直接替换 SD 里的组件

**核心思路**：SD 长驻作唯一启动源。开发期主机上有网，直接用 **SSH(scp) 或 FTP 登录开发板**，把改动的**组件**传上去、在板上挂载 SD 的 boot 分区覆盖，`reboot` 即生效。**不用 WSL 插读卡器、不重分区、不重刷 rootfs**。

```text
主机(改代码) --ssh/scp 或 ftp--> 开发板(已跑 Linux)
                                  │  mount boot 分区(FAT)
                                  │  覆盖 BOOT.bin / image.ub / boot.scr
                                  ▼  reboot 即生效
SD(唯一启动 = BOOT 分区)
```

> 关键：**改了什么就只替换哪个文件**。先确认板子支持哪条通道——`ssh` 一般都有；FTP 要看板上是否装了 `vsftpd`/`tftpd` 等服务（板上 `ps aux | grep -i ftp`、`netstat -tlnp | grep -E ':21\\|:69'` 查）。

### 4.1 改了什么 → 替换哪个文件（对照）

| 你要改的东西 | 只替换这个文件 | 重启后 | 备注 |
|---|---|---|---|
| 内核 / 设备树(DT) / ramdisk | `image.ub` | 新内核+DT 生效 | 最常见的增量更新 |
| U-Boot / FSBL / 把 bit 打进启动 | `BOOT.bin` | bootROM→FSBL→U-Boot 全用新版 | 启动级改动才需要 |
| 启动环境参数 | `boot.scr`（或 U-Boot env） | 新参数生效 | — |

> FPGA 的 `.bit` 不能单独丢进 FAT 生效，**必须打进 `BOOT.bin`**（见 §4.3 坑 1）。

### 4.2 板上哪块盘/boot/fs 是什么（先分清再操作）

以本板实际查得为准：SD 槽插着两张卡，系统都自动挂到 `/media/`（`findmnt` 看；板上可能没 `lsblk`，用 `cat /proc/partitions`）：

| 整盘 | 型号 | 容量 | boot 分区(99MiB FAT) | rootfs(ext4) | 挂载点(已自动挂) |
|---|---|---|---|---|---|
| **`/dev/mmcblk0`** | MSSD0 | ~29G | `mmcblk0p1`（**完整新镜像**） | `mmcblk0p2` | `/media/sd-mmcblk0p1`、`/media/sd-mmcblk0p2` |
| `/dev/mmcblk1` | IS008G | ~7.3G | `mmcblk1p1`（旧镜像，出厂卡） | `mmcblk1p2` | `/media/sd-mmcblk1p1`、`/media/sd-mmcblk1p2` |

> - **boot 分区固定 100MiB**（分区表 1MiB→100MiB，FAT 表头耗 ~1MiB，Filesystem 显示 ~97-99MiB）。boot 是 vfat、fs 是 ext4。
> - 本工程主力板卡是 **`mmcblk0`**：**boot=`/dev/mmcblk0p1`、rootfs=`/dev/mmcblk0p2`**。deploy 目标设备传 `mmcblk0` 即覆盖这两分区。
> - ⚠️ **两种 BOOT 文件写法要分清**：工程新镜像里是 **`BOOT.BIN`（大写）**（配套 `image.ub`/`boot.scr`/`u-boot.bin`/`system.bit`/`system.dtb`）；出厂旧卡里是 `BOOT.bin`（小写，配 `uImage`/`devicetree.dtb`/`system.bit.bin`）。覆盖时认准大写 `BOOT.BIN`。
> - 若板上跑的是出厂 ramdisk（`/` 挂 `rootfs` 而非某 SD 分区），说明系统从 ramdisk 起、SD 仅是存储，bootROM 实际从哪张卡起取决于拨码 + 插入的卡。

### 4.3 操作一：用 flash-sd.sh deploy（推荐，自动找分区+校验卡）

```bash
# 目标统一为板上大卡 mmcblk0（boot=mmcblk0p1 / rootfs=mmcblk0p2）
./utils/flash-sd.sh deploy -b ./src/images/linux root@10.10.10.93 mmcblk0   # 只同步启动模块
./utils/flash-sd.sh deploy -f ./我的rootfs root@10.10.10.93 mmcblk0         # 增量+镜像删除同步(自动自举板上 rsync)
```
> deploy 会自动 SSH 连板、校验 `mmcblk0` 为 SD 卡(removable=1 或 device/type=SD)、按 fstype 从 `/proc/mounts` 找到 `vfat`(boot)/`ext4`(rootfs)分区挂载点。`-b` 用 **scp** 只增不删;`-f` 用 **`rsync -a --delete --delete-during --numeric-ids`** 做增量+镜像删除(目标与源严格一致:源里删掉的板上也删,保留权限/软链)。同步后自动 `sync` 卸载。
>
> #### 留意：rsync 是怎么"装上"这块板的（本文板已做；新板照抄）
> 板是 busybox/dropbear、**无 rsync**，且 `/` 是 initramfs(ram，重启即丢)。做法：
> 1. 主机交叉**静态**编译 rsync(armv7)，需**关掉 FORTIFY_SOURCE**——否则静态版在板上跑同步会 `buffer overflow detected: terminated`：
>    `CC=arm-linux-gnueabihf-gcc ./configure --host=arm-linux-gnueabihf --disable-acl --disable-xattr --disable-lz4 --disable-zstd --disable-openssl --with-included-popt LDFLAGS='-static -U_FORTIFY_SOURCE' CFLAGS='-Os -U_FORTIFY_SOURCE' && make`
> 2. 产物放到板上 **boot(vfat) 分区 `tools/rsync`** 当持久副本(重启不丢，且任何 deploy 都不会删它)：
>    `ssh root@<IP> 'umount /media/sd-mmcblk0p1; mkdir -p /mnt/rs; mount -t vfat /dev/mmcblk0p1 /mnt/rs'`
>    `scp rsync root@<IP>:/mnt/rs/tools/rsync && ssh root@<IP> 'chmod 755 /mnt/rs/tools/rsync'`
> 3. `-f` 每次自动从任一已挂载 vfat 分区把 `tools/rsync` 自举复制到 `/usr/bin`(PATH 内)再同步。
> 4. **必须配 `--numeric-ids`**：静态 rsync 默认要做 uid/gid→用户名 NSS 查询，板无 NSS 库会段错误；用纯数字 id 规避(脚本已带)。

### 4.4 操作二：手 scp + 板上挂载（不依赖 deploy，同理）

前提：板上已跑 Linux、能联网；主机能 SSH 到板（`ssh root@<板IP>`）。boot 是 FAT32 `mmcblk0p1`（设备号以板上 `cat /proc/partitions` 为准）。

```bash
# ① 主机侧：把新组件推到板上（scp，走 ssh 通道）
scp ./BOOT.BIN ./image.ub ./boot.scr root@<板IP>:/tmp/

# ② 板上侧：挂载自身 boot 分区，覆盖目标文件
ssh root@<板IP>
mount -t vfat /dev/mmcblk0p1 /mnt      # 只用 boot 分区，rootfs 不动；可换 /media/sd-mmcblk0p1 已挂的
cp /tmp/BOOT.BIN /tmp/image.ub /tmp/boot.scr /mnt/
sync; umount /mnt
reboot                                # 重启即生效
```

> 只覆盖目标文件（如只换 `image.ub`），别把整个 FAT 清空覆盖，避免误删 `boot.scr`。

### 4.5 关键坑（务必注意）

1. **`.bit` 必须打进 `BOOT.BIN`**：FPGA 逻辑靠 FSBL 启动时配置，只往 FAT 放 `.bit` 不会生效。要 `petalinux-package --boot --fsbl fsbl.elf --fpga 新.bit --uboot` 重打 `BOOT.BIN` 再替换。
2. **换了 bit 且接口/地址/新增外设变化 → 必须同步换 `image.ub` 里的 DT**：否则新 PL 硬不起来、驱动不 probe（新 bit + 新 DT 一起重启才生效）。
3. 替换 `BOOT.BIN` 前确认新 FSBL 的 `ps7_init` / 时钟与板载匹配，否则可能起不来（保留旧 `BOOT.BIN` 便于回退，如 `cp /mnt/BOOT.BIN /mnt/BOOT.BIN.bak`）。

> 补充：若板上跑 FTP（`vsftpd`/`tftpd`）也可改用 FTP 传文件，方法与 scp 同理、免装 sshd；`tftp` 需配 TFTP 根目录。日常以 **SSH(scp)** 最省事。

## 5. QSPI 烧写方式（脱机/量产）

把 `BOOT.bin`（含或不含 `.bit`）写入板上 NOR Flash，拨码切到 QSPI 即可不插卡直接启动。**区别于 §3 的 SD**：QSPI 掉电保留、适合量产/脱机。

### 5.1 三种写入途径（任选其一）

| 途径 | 手段 | 适用 |
|---|---|---|
| **U-Boot** | `sf probe; sf erase; sf write` | 已能从 SD/QSPI 起 U-Boot、想原地升级 |
| **Linux** | `flashcp BOOT.bin /dev/mtdX` | 已起的 Linux 中在线更新 Flash |
| **JTAG (Vitis/XSCT)** | `program_flash -flash_type qspi-x4-single -fsbl … -file BOOT.bin` | 板子啥也起不来、首次烧 QSPI |

### 5.2 U-Boot 写 QSPI 示例
```
sf probe
sf erase 0x0 0x1000000        # 视 Flash 大小擦除（本板常为 16M）
sf write 0x2000000 BOOT.bin 0x1000000
```

### 5.3 Linux 写 QSPI 示例
```bash
flashcp -v BOOT.bin /dev/mtd0   # 设备号用 mtdinfo 确认
```

> 写完后需把拨码切到 **QSPI** 并断电重启，bootROM 才会从 QSPI 启动。

## 6. 何时用什么（速查）

| 需求 | 最优方式 |
|---|---|
| 日常快速出可启动镜像 | **SD**（FAT 拷 BOOT.bin/image.ub） |
| 反复改 kernel/dt/驱动/应用 | **SSH 登板换 SD 组件**（§4，重启生效） |
| 调 PL 纯逻辑（3-1 类实验） | **JTAG**（Vivado 下载 bit） |
| Linux 运行中换 PL bit、接口不变 | **JTAG 重配** + Linux 协同调试 |
| 脱机 / 量产 | **QSPI**（含 bit 的 BOOT.bin） |

## 7. 工具依赖速查

| 工具 | 用途 | 是否必需（只做 Linux） |
|---|---|---|
| Vivado | 建硬件工程、管脚/时序、导出 `.xsa` | ✅ 必需 |
| Vitis(SDK) | 写/调试 PS 裸板、生成 FSBL | ⭕ 不写裸板则不需要（FSBL 由 PetaLinux 自动生成） |
| PetaLinux | 构建打包 Linux、BOOT.bin | ✅ 必需（在做本项目） |
| sshpass | deploy 子命令 SSH 登板同步（`flash-sd.sh deploy` 自动装） | ⭕ 只用 §4.4 手 scp 则不需要 |
| rsync | deploy -f 增量+镜像删除。产物放板上 boot 分区 `tools/rsync` 自举 | ⭕ 只同步 boot 则不需要 |
| `cat /proc/partitions`（板上） | 板上无 `lsblk` 时确认分区设备号 | ✅ 排错常用 |
